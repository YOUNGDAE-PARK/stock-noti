# Stock-Noti 프로젝트 기본 설계서

이 시스템은 내가 보유한 종목과 ETF를 기준으로 매도, 추가 매수(추매), 보유 등의 판단을 돕기 위해 공식 이벤트, 뉴스, 시장 데이터, 리스크 알림을 중복 없이 수집하고 요약·정리하는 것을 목표로 합니다.

---

## 1. 핵심 원칙 (Core Principles)

### 원칙 1. 전체 시장 수집 금지
* 이 시스템은 뉴스 수집기가 아닙니다. 
* 전체 종목 뉴스 수집, 테마주 탐색, 언론사 RSS 대량 수집 등은 일절 진행하지 않습니다.
* 수집 대상은 오직 아래 범주로 제한합니다:
  * **내 보유 종목**
  * **내 보유 ETF**
  * **일부 관심 종목**
  * **보유 ETF의 핵심 구성종목 일부**

### 원칙 2. 기사 단위가 아닌 이벤트 단위 저장
* 같은 사건에 대한 여러 기사들을 각각 개별 수집하는 대신, 하나의 **투자 이벤트**로 병합하여 저장합니다.
* *예시:*
  * A사 공급계약 공시 + A사 공급계약 보도자료 + A사 대형 수주 기사
  * $\rightarrow$ **하나의 이벤트:** `A사 대규모 공급계약 발생`으로 병합

### 원칙 3. 판단 근거는 공식 소스 우선
* 수집 데이터의 신뢰도와 근거 우선순위는 다음과 같습니다.
  $$\text{DART} \rightarrow \text{기업 IR / 뉴스룸} \rightarrow \text{KIND} \rightarrow \text{네이버 뉴스} \rightarrow \text{기타 보조 데이터}$$
* 뉴스는 현상의 포착 수단으로만 사용하고, 최종 판단은 가급적 DART나 기업 공식 발표 등의 1차 출처로 재확인합니다.

## 2. 수집 소스 및 수집 범위

| 구분 | 소스 | 역할 | 우선순위 | 수집 주기 | 상세 내용 |
| :--- | :--- | :--- | :---: | :---: | :--- |
| **공식 공시** | **DART** | 종목별 공식 공시, 실적, 주요사항, 증자, 계약, 배당 등 | 1 | 1일 2회 (관심 1회) | OpenDART API 활용 (`crtfc_key` 및 `corp_code` 매핑 필요) |
| **공식 발표** | **기업 IR / 뉴스룸** | 실적자료, 보도자료, 주주서한, 수주, 신제품, 증설 정보 | 2 | 1일 1회 | 보유종목별 공식 URL 레지스트리 관리 (뉴스룸 접속 실패 시 AI 탐색) |
| **리스크 보완** | **KIND** | 거래정지, 관리종목, 불성실공시, 투자주의·경고·위험 등 | 3 | 1일 1회 / 실시간 연동 | KIND RSS 및 공시 화면 기반 감시 |
| **언론 반응** | **네이버 뉴스** | 공시·IR 이후 해석, 악재 확산, 리포트성 기사 확인 | 4 | 1일 1회 / 1시간 주기 | 네이버 뉴스 검색 API 사용 (종목별 맞춤 키워드 쿼리 적용) |
| **시장 데이터** | **KRX Open API** | 일별 가격, 거래량, ETF 데이터, 지수, 시장 통계 | 5 | 장 종료 후 1회 / 1시간 주기 | KRX Open API 기반 일별 가격 및 시황 데이터 수집 |

## 3. 시스템 아키텍처

```
[내 보유자산 목록] (종목/ETF, 목표 비중, 현재 비중, 보유이유, 리스크 키워드)
        │
        ▼
[수집 계층 (Collector)]
  ├── DART API (최근 공시)
  ├── 기업 IR / 뉴스룸 (RSS 또는 크롤링)
  ├── 네이버 뉴스 API (보유 이유 맞춤형 쿼리)
  ├── KIND RSS (거래정지 등 리스크 공시)
  └── KRX Open API (종가, 거래량, KOSPI/KOSDAQ 지수)
        │
        ▼
[정규화 계층 (Normalization)]
  └── 종목코드 매핑, 날짜 통일, 소스 신뢰도 부여, 초과수익률(Excess Return) 계산
        │
        ▼
[이벤트 병합 계층 (Event Consolidation)]
  └── 동일 종목 + 유사 날짜(1~3일) + 동일 이벤트 유형 + 키워드 매핑
        │
        ▼
[전문 판단 계층 (Professional AI Engine)]
  └── Thesis Alignment + Market Relative + Valuation Layer + Portfolio Constraints
        │
        ▼
[알림 및 리포트 계층 (Multi-channel Delivery)]
  ├── SLACK_URGENT : 실시간 단기 리포트 (이벤트 감지 시 즉시)
  ├── SLACK_DAILY  : 오전 8시 일일 종합 리포트
  └── SLACK_WEEKLY : 주간 운영 및 리밸런싱 제안
```

## 5. 이벤트 병합 및 판단 신호 생성 규칙

### 5.1 1차 중복 제거 (원천 단위)
* `source_type` + `url` + `title_normalized` + `published_at`을 조합하여 해시값을 계산하고, 기존 DB에 동일한 해시값이 있을 경우 수집을 건너뜁니다.

### 5.2 2차 중복 제거 (이벤트 병합)
* 아래 조건을 만족할 경우 개별 원천 아이템을 하나의 **`investment_event`**로 묶고 대표 근거와 연결합니다:
  * **같은 `ticker`**
  * **같은 `event_type`**
  * **시간대 유사성:** 발행 시간 차이가 1~3일 이내
  * **텍스트 유사성:** 제목의 유사 단어 및 키워드가 매칭되는 경우
* 대표 근거는 우선순위(DART $\rightarrow$ IR $\rightarrow$ KIND $\rightarrow$ 네이버 뉴스)에 의해 1개만 선정되고, 나머지는 `event_source_link`로 연결됩니다.

### 5.3 전문 AI 판단 엔진 (Professional Logic)
*   **Thesis Alignment (최우선)**: 발생한 이벤트가 사용자의 **'보유 이유(Investment Thesis)'**를 강화하는지, 혹은 핵심 논리를 훼손하는지를 분석합니다.
*   **Market-Relative Performance**: 단순히 절대 등락률을 보는 대신, 해당 시장 지수(KOSPI/KOSDAQ) 대비 **'초과 수익률(Excess Return)'**을 통해 시장의 실제 반응을 해석합니다. (예: 지수가 2% 오를 때 종목이 1% 오르면 약세로 판정)
*   **Portfolio Guardrails**: 현재 비중이 **'목표 비중'**을 초과했거나 **'최대 비중'**에 도달한 경우, 아무리 호재가 발생해도 '추매검토' 대신 **'보유'**를 제안하여 리스크 쏠림을 방지합니다.
*   **Structured Reasoning**: AI 판단 근거는 단순히 텍스트 나열이 아닌, **[판단 요약], [긍정 요인], [리스크/반대 논리], [불확실성], [향후 체크 포인트]**의 입체적인 구조로 제공합니다.
*   **Noise Filtering**: 시장 영향이 없고 반복적인 단순 행정 공시는 AI 호출 없이 시스템이 자동 처리(`[시스템 자동처리]` 태그 부여)하여 노이즈를 줄이고 비용을 최적화합니다.

## 7. 중복 제거 설계
* **1차 중복 제거 (원천 단위):** `source_type` + `url` + `title_normalized` + `published_at` 조합의 고유 해시(`raw_hash`)를 기준으로 데이터 적재 단계에서 차단.
* **2차 중복 제거 (이벤트 단위):** `ticker` + `event_type` + `1~3일 이내 발행일` + `대표 키워드`가 유사할 경우, 신규 `investment_event`를 생성하지 않고 기존 이벤트에 보조 자료(`event_source_link`)로 병합.

## 8. 전문 판단 프로세스 및 규칙
*   **Batch Analysis**: 토큰 효율성을 위해 여러 이벤트를 묶어 한 번의 AI 호출로 처리하며, 펀드매니저 페르소나를 부여하여 분석의 전문성을 확보합니다.
*   **Decision Prioritization**:
    1.  보유 이유 훼손 여부 확인 (훼손 시 즉시 '매도검토' 또는 '비중축소')
    2.  시장 지수 대비 상대 강도 확인 (호재 시에도 지수 대비 약하면 '보유' 또는 '비중축소')
    3.  포트폴리오 비중 제약 확인 (목표 비중 초과 시 '추매' 제한)
*   **Final Output**: 사용자에게 행동 지침과 함께 균형 잡힌 시각(Pros & Cons)을 제공하여 독자적인 판단을 지원합니다.

## 9. 일일 운영 및 스케줄링 플로우

### 9.1 오전 8:00 (일일 종합 리포트 발행)
* **목표:** 전일까지 수집되어 이벤트 병합이 완료된 고신뢰 데이터를 바탕으로, 금일 투자 결정을 돕기 위한 **종합 리포트**를 발행합니다.
* **대상 데이터:** 전일 수집된 DART 공시, IR 공식 발표, KRX 종가/거래량, KIND 공시 및 네이버 뉴스로부터 통합된 2차 투자 이벤트.
* **출력 항목:** 오늘의 중요 이벤트, 보유종목 위험도 리포트, 리밸런싱 제안.

### 9.2 매 1시간 주기 (실시간 단기 분석 루프)
* **목표:** 장중 돌발 변동성 및 속보 뉴스에 즉각 대처합니다.
* **수집 및 분석 대상:**
  * 현재 시점의 실시간/지연 주가 흐름 (급등락 및 거래량 추이)
  * 최근 1시간 이내 발행된 속보/실시간 뉴스 (네이버 뉴스 API 쿼리)
  * 실시간 DART 공시 및 KIND 시장조치 사항
* **알림(Noti) 및 단기 리포트 발행 조건:**
  * 주가 변동성이 임계치(예: $\pm5\%$ 이상 급등락)를 초과한 경우
  * 보유종목의 **리스크 키워드**에 매칭되는 강력한 실시간 뉴스가 검출된 경우
  * DART 및 KIND로부터 즉각적인 고위험 공시(거래정지, 유상증자 결정 등)가 발생한 경우
  * **★ 생략 규칙:** 분석 시점에 위의 위험 및 특이사항이 발견되지 않는 경우, **알림과 리포트 출력을 완전히 생략**하여 불필요한 노이즈를 방지합니다.

### 9.3 장 종료 후 (일괄 데이터 적재 및 정제)
* **목표:** 하루의 공식 시장 데이터를 수집하고 데이터를 정규화 및 병합하여 데이터베이스를 최신 상태로 갱신합니다.
* **수행 태스크:**
  1. KRX를 통한 종가, 거래대금, 시가총액 수집
  2. 당일 전체 네이버 뉴스 및 IR/뉴스룸 게시글 확인
  3. 1차 해시 기반 중복 제거 및 2차 이벤트 병합 수행
  4. 다음날 오전 8시 종합 리포트 발행에 필요한 스냅샷 준비

## 10. 구현 단계별 계획

* **Phase 0 — 키 발급 및 환경 준비:** API 키 연동, SQLite 데이터베이스 설계 및 연결 모듈 작성.
* **Phase 1 — 보유자산 마스터 구축:** 보유자산 테이블에 모니터링할 포트폴리오를 입력하고 DART `corp_code` 자동 매핑 구현.
* **Phase 2 — DART 수집기 구현:** 공시 수집 및 파싱.
* **Phase 3 — 네이버 뉴스 API 수집기 구현:** 종목/보유이유 매칭 뉴스 수집.
* **Phase 4 — IR / 뉴스룸 레지스트리 구축:** 보유종목의 공식 사이트 매핑 및 AI 보조 갱신 로직 구현.
* **Phase 5 — KRX 시장 데이터 수집:** 일별 종가, 거래량 적재.
* **Phase 6 — KIND 리스크 보조 수집:** 거래정지 및 경고 종목 수집.
* **Phase 7 — 정규화 및 이벤트 병합 계층 구현:** 1, 2차 중복 제거 엔진 작성.
* **Phase 8 — 스케줄러 & 리포팅 모듈 구현:** 
  * 오전 8시 종합 리포트 발행 엔진 구축
  * 매 1시간 주기 단기 분석 및 Noti 필터링(필요 없는 경우 생략) 스케줄러 구축
  * 알림 채널(콘솔 / 파일 / 메신저 등) 연결

## 11. 최종 MVP 범위
* **수집 모듈:** DART, 네이버 뉴스, KRX 일별, KIND RSS, IR 레지스트리.
